Core Capabilities

Designed for Reliability & Precision

Engineered with modern database principles to handle concurrent bookings, prevent double-seat allocation, and provide accurate live tracking.

ACID Transaction Safety

Atomicity, Consistency, Isolation, and Durability ensure that multiple simultaneous ticket reservations never result in double-booking or inconsistent states.

Secure Bcrypt Hashing

Passwords are never stored in plaintext. They undergo salt-based hashing using bcryptjs, securing passenger credentials against unauthorized access.

Instant PNR & E-Ticket

Automated 10-digit PNR generation with structured seat allocations, chart preparation states, and digital PDF ticket download readiness.

Frequently Asked Questions

Common queries regarding Railway reservation & DBMS operation

How does the system ensure no two passengers get the same seat?

The backend utilizes SQL transactional locks (`BEGIN TRANSACTION ... COMMIT`) and unique constraints on `(train_number, journey_date, seat_number)` so race conditions are impossible.

What happens when I register an account?

Your user record is added to the MySQL `users` table via `POST /api/register`. Passwords are encrypted using bcrypt salt-10 rounds. You can immediately log in with your email.

What is the PNR status format?

PNR stands for Passenger Name Record, a unique 10-digit key stored in the `bookings` table. It contains passenger details, train number, travel date, fare, and confirmation status.
